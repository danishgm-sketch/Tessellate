## Security headers

The Sites Worker routes public HTML through the edge adapter while preserving the vetted body, generated CSP hashes, and the static asset cache policy. Public HTML does not receive `no-transform`, allowing transparent compression without changing decoded markup or its CSP hashes. The isolated `/preview` wrapper and `/preview-content` renderer retain `no-transform` to protect their exact iframe/CSP contract. Packaging hashes inline scripts and style elements across public HTML files, excluding those isolated preview routes. `/preview` is a small trusted wrapper; the actual React renderer runs in a child iframe with both an iframe `sandbox="allow-scripts"` attribute and a response-level `sandbox allow-scripts` CSP. Top-level browser navigations to `/preview-content` are redirected to the wrapper. The renderer has an opaque origin and cannot access the application DOM or storage. Its CSP blocks arbitrary network connections, nested frames, and external assets; the only `connect-src` exception is the same-origin immutable `/_astro/` asset path used by its stylesheet preload. The child renderer response omits `frame-ancestors` and `X-Frame-Options` because the intentionally opaque sandbox parent cannot satisfy a same-origin ancestor check; sandboxing remains enforced on the response and iframe. Resource links are sent as bounded typed requests only after a trusted anchor click. The trusted host validates the source frame, opaque origin, and HTTP(S) destination, then shows an accessible confirmation link; it does not navigate automatically or grant top-navigation permission.

The app embeds `/preview-content` directly for interactive resource details and catalogue cards. The renderer validates that updates come from its direct parent and that the message sender has the Site origin; its own opaque origin is not the sender origin. READY/resize/error/navigation messages flowing back to the app are accepted only from the matching iframe with the expected opaque `null` origin. The top-level `/preview` wrapper supplies initial state from the URL and presents the same explicit navigation confirmation for requested links.

Preview CSP also explicitly sets `form-action 'none'`, and the app shell allows only same-origin form destinations. A desktop/mobile Playwright probe attempted to submit a field to an intercepted external collector: no request was emitted. Before the explicit directive was added, the opaque sandbox already blocked submission, but the header had no dedicated form-action rule. Registry admission now also rejects unresolved `action`, `formAction`, and `ping` props; shared link, button, and input primitives strip those forwarding props.

Historical note: on 2026-10-21 the earlier deployed Site had a broad app-shell policy with unsafe-inline in script-src and style-src, and an injected inline script executed. The later public v30 deployment uses generated script and style hashes; desktop/mobile CSP checks passed and AUD-268 closed after deployed verification. Public v32 still reproduces AUD-342: the Sites-injected bootstrap is blocked by the strict app-shell CSP. The current source candidate adds a fresh per-response nonce to public HTML's script policy while retaining the generated hashes, strict preview policies and compression-friendly HTML cache headers. This follows [Cloudflare's documented CSP integration](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/javascript-detections/). Its regression verifies nonce rotation, unchanged HTML, no `unsafe-inline`, and no nonce on sandboxed preview routes. This is local evidence only: AUD-342 remains pending until an exact saved candidate is deployed and the injected bootstrap is shown to run without a CSP error. See `quality/evidence/step-37/site-shell-csp-hardening.json`, `quality/STEP_37_EVIDENCE.md`, and `audit/RUNTIME_AUDIT.md`.
