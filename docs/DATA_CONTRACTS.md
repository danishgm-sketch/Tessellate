# Tessellate Data Contracts

All core product behaviour is driven by typed, versioned, validated data contracts. The runtime must not maintain parallel ad-hoc object shapes that drift from these definitions.

The canonical TypeScript/Zod implementations belong in `packages/schemas` once code generation begins.

## 1. Contract rules

1. Every persisted top-level object has `schemaVersion`.
2. IDs are opaque strings generated by one shared helper.
3. Unknown fields are rejected at external boundaries unless a migration explicitly handles them.
4. Persisted enums are stable. Renaming an enum requires migration.
5. Numeric Design DNA values are integers 0–100.
6. Optional fields are truly optional; avoid nullable-and-optional ambiguity unless storage semantics require it.
7. Dates are ISO 8601 strings in persisted JSON.
8. Resource code never carries authoritative metadata duplicated from manifest.
9. Project mutations target stable semantic node IDs, not array offsets.
10. Schemas must be serialisable to JSON Schema where feasible for agent/API consumption.

## 28. AI provider configuration

Provider credentials are runtime-only and are not part of persisted project manifests.

Persist only non-secret preferences, e.g. provider type/model preference if user explicitly chooses to save them locally.

## 30. Migration policy

Maintain:

```text
packages/schemas/src/migrations/
```

Each persisted schema version gets explicit migrations.

Rules:
- migrations are deterministic;
- migrations are tested with fixtures;
- raw invalid user data is preserved before destructive recovery;
- no silent project reset;
- export command can migrate older manifest to current version.
