# Feature test matrix

Captured 2026-10-16 after the green baseline. The matrix covers all 158 rows in docs/CURRENT_PRODUCT_INVENTORY.md.

FAIL currently means feature-specific evidence for that dimension has not yet been recorded in this matrix; it does not assert that the runtime is known to fail. Generic baseline tests are not promoted to feature-level PASS without a named assertion and result. Use NOT APPLICABLE only when the feature has no such behavior; use LAB ONLY only for an explicitly isolated Lab check.

No capability tier is certified by this matrix. Step 04 records selected UI-scoped results; the laptop proposal flow uses a controlled API fixture and certifies review/apply state handling, not model quality or live-host reliability. Replace a status only after attaching the exact automated or observed evidence in the relevant hardening gate.

Step 06 adds named local Sites Worker browser evidence for all 324 default previews at seven widths and all 972 declared catalogue variants at desktop width; the 40-resource Gold matrix covers all 120 Gold variants at seven widths, keyboard behavior for enabled controls, reduced motion and iframe isolation. A focused 13-resource navigation/control regression covers placeholder destinations and visible actions. The final official `pnpm test:e2e` run passed (73 regular tests, 11 explicit skips, and 3/3 Sites Worker tests); the catalogue and Gold reports record zero findings. The catalogue responsive/variant cells now record PASS for the tested render contract; unexecuted semantics, states and network conditions remain FAIL. Local fixes remain open pending published review verification. Evidence is in `quality/STEP_06_EVIDENCE.md` and `audit/evidence/step-06/results/`.

Step 09 adds a no-override 100-brief Product Interpreter benchmark with semantic
signals, metric ranges and contamination checks. The Product Interpreter row
records only the dimensions covered by that benchmark; untested error, browser,
security and performance dimensions remain FAIL. See `quality/STEP_09_EVIDENCE.md`.

Step 10 adds a no-override 100-brief Screen Planner benchmark. It checks exact
recommendation semantics, route uniqueness, graph reachability, target-device
metadata, mobile navigation limits, unknown screen grammars, and the no-recommendation
fallback. Screen planner results remain local engine evidence; deployed visual and
browser validation is scheduled with the later Compose and RC gates.

Step 11 records the tested Design DNA dimensions in `quality/STEP_11_EVIDENCE.md`.
Only the happy path, numeric boundaries, desktop rendering, keyboard slider input,
console errors and network errors have feature-specific PASS evidence so far.
Mobile has screenshot-only DEGRADED evidence; all other untested matrix dimensions
remain FAIL. Catalog categorical uniformity and metadata-only `contentTone` are
explicitly tracked rather than treated as working effects.

Step 12 adds an exact-brief desktop browser journey through Compose and all three
full-screen previews. It verifies three distinct root hierarchies, navigation
models and grammars, the shared seven-screen product plan, real resource references,
unresolved-role diagnostics, screenshot evidence and browser/network errors. A
failing pre-fix assertions reproduced Direction C's unoccupied right content pane,
misaligned table/stream rows and duplicate activity resource. The shared renderer
now places the data table and activity stream in aligned desktop columns; the structural alternative selects
the existing Gold Timeline resource for its contextual stream. The matrix records
only the happy path, desktop, browser-console and network checks as PASS. Responsive
widths, assistive technology, error states and deployed review validation remain
FAIL until their named gates run. See `quality/STEP_12_EVIDENCE.md`.
