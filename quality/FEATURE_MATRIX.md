# Feature test matrix

Initial matrix captured 2026-10-16 after the green baseline. Step-specific evidence below extends it; the matrix covers all 158 rows in docs/CURRENT_PRODUCT_INVENTORY.md.

FAIL currently means feature-specific evidence for that dimension has not yet been recorded in this matrix; it does not assert that the runtime is known to fail. Generic baseline tests are not promoted to feature-level PASS without a named assertion and result. Use NOT APPLICABLE only when the feature has no such behavior; use LAB ONLY only for an explicitly isolated Lab check.

No capability tier is certified by this matrix. Step 04 records selected UI-scoped results; Step 32 separately verifies the local Docker queue and host runtime, but does not certify model quality, a public tunnel, or deployed bindings. Replace a status only after attaching the exact automated or observed evidence in the relevant hardening gate.

Step 35 accessibility evidence (2026-10-20): the Sites Worker Chromium audit scanned Home, Explore, Compose, Workbench, Button detail, isolated Button preview and one representative showcase at 1440×900 and 390×844. WCAG 2.0/2.1/2.2 A/AA and target-size Axe checks reported zero violations on all routes. All five Workbench modes and five mobile tabs also had zero violations. The browser accessibility tree was captured as a screen-reader semantic smoke check; keyboard checks covered skip targets, desktop search, mobile navigation, Explore filters and desktop layer reordering. Reduced motion and color contrast rules passed in the states tested. Route screenshots and runtime records show zero console errors, uncaught exceptions, failed requests, HTTP errors or horizontal overflow. A later all-Gold 120-variant Sites Worker run caught and closed one serious Nocturne badge contrast defect (3.38:1 before; no Axe finding after the fix); see the follow-up finding and captures. This is evidence for those named surfaces and states only; it does not certify every matrix row or all keyboard operations. Native browser zoom and spoken NVDA/VoiceOver output remain unverified. See `quality/STEP_35_EVIDENCE.md` and `quality/evidence/step-35/`.

Step 36 responsive evidence (2026-10-20): 14 representative major routes were exercised at 360, 390, 430, 768, 1024, 1280, 1440 and 1536 CSS pixels in desktop Chromium and Pixel 7 Chromium emulation (224 route/viewport pairs). Navigation, Explore filters, Workbench panels/tabs, and Compose were interacted with at the applicable widths; Compose generated three directions at each width. Two reproduced medium layout defects were fixed and covered by red/green regressions. This result covers the named routes and interactions only; untested catalogue resources, Firefox/WebKit, and all matrix dimensions remain unverified. See `quality/STEP_36_EVIDENCE.md` and `quality/evidence/step-36/`.
